## Decisões arquiteturais importantes

1. **Skills > commands para novo conteúdo** — per doc oficial Claude Code 2026, skills são o formato recomendado pra workflows multi-step. v4.3.0 migrou `/bugfix` de command para skill; v4.4.0 estendeu pra `bugfix-light` e `bugfix-heavy`.

2. **Approach A (markdown prescritivo) + Approach C (execução híbrida)** — cada step é markdown prescritivo no estilo Pulsar; execução é híbrida (steps de análise → subagent isolado, steps de decisão → inline).

3. **Sync canonical D:\ ← cache C:\ 4.1.3 antes de qualquer Slice 1+** — descoberto em 2026-04-30 que canonical estava 97 commits atrás. Sem o sync, todo design v5 estava num baseline irreal.

4. **commands/pipeline.md NÃO foi deletado** — apesar do plugin-validator sugerir consolidação skill-only, o command tem inline-invariants que servem como referência arquitetural. Decisão consciente de manter; revisar em Slice 3.

5. **Os 3 agents type-specific bugfix-\* mantidos** — em vez de deletar e mover lógica pras skills, mantemos os agents existentes e os referenciamos nos novos steps. Zero quebra de retrocompat.
