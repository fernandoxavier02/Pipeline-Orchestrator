The audit method

The pipeline-orchestrator plugin was audited against itself using a real project (IFRS 16 lease-accounting webapp) as the test bench. Seven scenarios across seven git worktrees, then a deep second pass over the 70% surface that the first pass missed.

Phase H Deep Audit

The 70% the first pass missed

Eight hooks read end-to-end. Official hook test suite revealed dispatch-guard table missing brainstorm-controller. Three more subagents (sanity-checker, checkpoint-validator, bugfix-regression-tester) caught falling back to prose despite the D2-extension append — fix required prominent top-of-file notes, not just appended sections. New findings: H1-002 sentinel-hook fail-open admitted by design, H1-003 STALE_THRESHOLD drift across three values (5min/10min/24h), H6-001 JSONL injection, H6-002 pipeline.local.md no strict parser.

10 untested registry gates exercised in runtime: PLAN_REJECTED, CHECKPOINT_FAIL, ADVERSARIAL_BLOCK, STOP_RULE, STEP_1_7_RECURSION_GUARD, STALE_CONTEXT, plus 4 spec gates. Six skill variants tested via their base agents. CONTINUE mode validated end-to-end.

STALE drift resolved (I7): new SSOT references/stale-thresholds.md documents three distinct concepts — STALE_SPAWN (5min), STALE_HEARTBEAT (10min), STALE_CONTEXT (24h). Hooks renamed to canonical constants with backward-compat aliases.

Retracted findings (transparency)

H8-NEW-001 — validate-trace exit code

The auditor (me) reported that scripts/validate-trace.cjs always returned exit 0 even on validation failure. The report was wrong: the test command used a pipe (| head -5) which captured head's exit code, not node's. Isolated re-test confirmed the script correctly returns exit 1 on failure. Finding withdrawn and documented in the Fase I report.
