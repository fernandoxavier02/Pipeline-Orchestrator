Achado #7

Emit & Hoist Protocol

Claude Code's harness strips AskUserQuestion, Agent, and EnterPlanMode from subagent runtime manifests. Instead of breaking, subagents emit structured YAML blocks. The parent reads them and dispatches the tools in its own context.

⚠️
The empirical fact

On 2026-05-07, an empirical probe confirmed: when a subagent is dispatched via the Agent tool, its runtime tool manifest does not include AskUserQuestion, Agent, or EnterPlanMode — regardless of what the agent's allowed-tools frontmatter declares. The harness strips them silently. A subagent that calls them gets tool not available at the harness layer.

Confirmed available in subagent runtime: Read, Write, Edit, Glob, Grep, Bash, Skill, Task* family, WebFetch, WebSearch.

The flow

When a subagent needs user input, plan-mode research, or to dispatch a sub-subagent, it emits a structured block in its tool result. The parent (you, in the main session) parses, dispatches the right tool in your own context, and re-invokes the subagent with the response prepended.

Three block types

GATE_REQUEST v1
User decision

Subagent needs the user to choose between 2-4 options. Parent invokes AskUserQuestion.

=== GATE_REQUEST v1 ===
gate_id: "<unique-id>"
question: "..."
multi_select: false
options:
  - label: "..."
    recommended: true
=== END GATE_REQUEST ===
STATUS: AWAITING_GATE_RESPONSES
DISPATCH_REQUEST v1
Sub-subagent dispatch

Subagent needs to call another agent or skill. Parent invokes Agent or Skill in its context.

=== DISPATCH_REQUEST v1 ===
dispatch_id: "..."
target_kind: agent
target_name: "..."
prompt: |
  ...
=== END DISPATCH_REQUEST ===
STATUS: AWAITING_DISPATCH_RESULTS
PLAN_MODE_REQUEST v1
Plan-mode research

Subagent (typically plan-architect) needs read-only research. Parent invokes EnterPlanMode.

=== PLAN_MODE_REQUEST v1 ===
plan_id: "..."
research_scope: |
  ...
expected_deliverables:
  - "..."
=== END PLAN_MODE_REQUEST ===
STATUS: AWAITING_PLAN_MODE_RESULTS

Why this matters

The bug it prevents

Without the explicit protocol, a subagent that tries to call AskUserQuestion directly silently fails. The LLM then improvises — typically writing the question in free prose ("Should we do A or B? Please tell me"). The parent has no way to parse that deterministically. The pipeline either deadlocks or the parent guesses an answer. Both outcomes corrupt the audit trail.

In v6.0.0, all 16 subagents that need user input or plan-mode research declare the protocol explicitly in their .md spec, with a worked example matching the canonical schema. The regression test D2_test_subagent_protocol.cjs validates this on every CI run.

Empirical evidence (v6.0.0 audit, 2026-05-15)

Before v6.0.0 fixes: information-gate emitted prose A/B questions when it detected a BLOCKER gap. After applying the protocol spec section to its .md, the same scenario produced a well-formed GATE_REQUEST v1 block with multi_select: false, recommended: true field, and AWAITING_GATE_RESPONSES status. Same evidence for plan-architect: before, inline plans without research; after, PLAN_MODE_REQUEST v1 with concrete plan_id and expected_deliverables.

The 16 subagents covered: information-gate, plan-architect, design-interrogator, pre-tester, executor-fix, executor-implementer-task, spec-closer, feature-implementer, bugfix-diagnostic-agent, bugfix-root-cause-analyzer, bugfix-regression-tester, ux-simulator, ux-accessibility-auditor, ux-qa-validator, architecture-reviewer, sanity-checker, checkpoint-validator.
