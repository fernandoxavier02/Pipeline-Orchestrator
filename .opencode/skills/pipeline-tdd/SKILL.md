# Pipeline TDD

Write the acceptance expectation first, then a failing test, then the smallest code change that passes.

Use structured question gates if a test boundary or allowed surface is unclear.

Reject missing evidence. No implementation starts without RED evidence, and no prompt runs without GREEN evidence.
